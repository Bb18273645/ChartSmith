## 长描述（可直接粘贴到「详细描述」）

**一句话**：让 AI 把流程、架构、调用链画成一张排版好的图片，直接发到 QQ / Telegram / 飞书里，而不是一堆文字。

聊天平台没有 DOM，AstrBot 的消息段只有 `Plain` / `Image` / `At` 这几种——所谓「卡片」只能是渲染好的位图。
图匠把这条链路做完了：**模型给结构 → 插件算布局 → 渲染 PNG → 当图片消息发出去**。

**它解决什么问题**

- 让模型画流程/架构，它只能吐 mermaid 源码或 ASCII 图，在手机上根本没法看；
- 直接截图 Markdown 表格，版式是「截图感」，达不到图文卡片的观感；
- 走远程文转图服务，每张图要过一次外网，内容离开本机，服务抖一下插件就报错。

图匠换成**本地渲染**：布局和绘制都在插件进程里完成，用 AstrBot 自带的 Pillow 出图，零额外依赖、离线可用。

**主要特性**

- **稳定的版式**：最长路径分层 + 两轮重心排序 + 正交走线；环、重试、回调这类回边走图外侧独立轨道，不会从别的节点背后穿过去。
- **手机优先**：默认 2 倍像素输出；自动在上下（TB）和左右（LR）里挑更窄的版本——手机按屏宽缩放，越窄字越大。
- **聊天友好**：图片和说明合成一条消息（QQ 一个气泡发完）；发图失败兜底成文字，不让群里静默。
- **模型无关**：JSON 契约里没有坐标字段，模型不用学布局，换哪家模型都一样。
- **不刷屏**：每会话每分钟限流、按内容哈希缓存（7 天 / 200 张）、超限节点自动截断并注明。
- **可调试**：`/diagram {JSON}` 与中文别名 `/图匠`，不经过模型直接出图排查链路。

**怎么用**

1. 安装后在 WebUI → 人格 → 你正在用的 persona，把仓库里 `提示词.md` 第 ① 节贴到系统提示词末尾；
2. 聊天里说「画一下登录流程」「画一下我们订单系统的架构」；
3. 图片直接发出来，模型再用一两句话补充结论。

调试：`/diagram {"title":"测试","nodes":[{"id":"a","label":"A"},{"id":"b","label":"B"}],"edges":[{"from":"a","to":"b"}]}`

**适用场景**

- 流程 / 架构 / 调用链 / 状态机 / 模块关系（3~16 个节点）
- 群聊里给别人解释系统怎么串起来的
- 把 Agent 的执行步骤、发布流水线可视化

**不适合**

- 纯数字对比、清单、代码（直接文字或表格更快）
- 20+ 节点的超大图（请分层画多张）
- 需要点击交互的图（聊天平台只能发静态图片）

**依赖与资源**

- 无第三方依赖，使用 AstrBot 内置的 Pillow；
- 中文字体自动探测（Windows 雅黑 / macOS 苹方 / Linux Noto CJK），Docker 里中文变方块时装 `fonts-noto-cjk` 或配置 `font_path`；
- 缓存写在 `data/plugin_data/astrbot_plugin_chartsmith/`，最多 200 张、7 天过期。

**隐私说明**

渲染全部在本机完成，不调用任何第三方文转图/渲染服务；图片只发到用户当前会话。
