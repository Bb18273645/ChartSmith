## 一、先看场景速查

| 你的用法 | 是否需要额外授权 | 必须做的事 |
|---|---|---|
| 自己群里 / 自己服务器上装来用 | 不需要 | 无（保留署名即可） |
| 学习、研究、改着玩 | 不需要 | 无 |
| 非营利组织、开源社区展示 | 不需要 | 无 |
| 改完自己用，不公开 | 不需要 | 无 |
| 改完公开分享（发群/发 GitHub） | 不需要额外授权 | **注明上下游 + 公开源码 + 沿用本许可** |
| 给朋友免费部署 | 建议先问一声 | 公开源码；不得收费 |
| 收费部署、代运维、定制开发 | **需要** | 取得作者书面同意 / 签商业授权 |
| 做成 SaaS、多租户服务收费 | **需要** | 同上 |
| 集成进公司生产经营系统 | **需要** | 同上 |
| 打包进付费课程、付费社群、付费插件市场 | **需要** | 同上 |
| 以本插件为主要卖点做商业宣传 | **需要** | 同上 |

> 判断标准很简单：**有没有赚到钱 / 换到商业利益**。赚了就要先拿到书面同意。

## 二、二改的强制义务（做一次就够，别漏）

### 1. 注明上下游关系

在下面三个位置都要写清楚：

- 项目 README 或「关于」页面首部；
- 发布说明 / 市场详情页 / 分发渠道的描述；
- 每个源文件头部（至少保留原作者版权行）。

**README 可直接复制的模板：**

```markdown
> 本作品基于 [ChartSmith](https://github.com/Bb18273645/astrbot_plugin_chartsmith)
> v0.2.0（作者 Bb18273645）修改。
>
> 修改内容：
> - 增加 xxx 图类型；
> - 调整了 xxx 的配色；
> - 修复了 xxx 的崩溃问题。
>
> 本作品沿用 ChartSmith 的社区许可（非商业使用免费、商业化需书面授权、修改必须开源）。
```

**源文件头部模板：**

```python
# 本文件基于 ChartSmith (https://github.com/Bb18273645/astrbot_plugin_chartsmith)
# v0.2.0 修改。原作者：Bb18273645。修改内容：<一句话>。
# 沿用 ChartSmith 社区许可，详见 LICENSE。
```

### 2. 公开完整源代码

- 用**本许可**或更严格的协议发布；
- 必须能构建运行（不能只发 pyc、混淆代码、二进制，也不能只开一个收费 SaaS）；
- 分发时要给出持续可访问的源码地址。

### 3. 保留署名与协议

- 不得删除、隐藏作者的版权行与 `LICENSE`；
- 不得把项目改名后声称原创；
- 不得暗示作者为你的修改、服务或公司背书；
- 不得在名称/Logo 里用「ChartSmith」「图匠」当主要标识，也不要用「官方」「正版」「合作」误导用户（写「兼容 ChartSmith」可以）。

### 4. 向下游传递

分发时把 `LICENSE` 一起给出去，并保证你下游的用户也受同样约束。

## 三、商业授权怎么申请

建议通过 GitHub Issue（标题加 `[商业授权]`）或作者主页列出的联系方式发起，内容包含：

```text
申请类型：商业授权
使用方：<公司/个人名称、注册地>
使用方式：<自用部署 / 对客户收费 / SaaS / 集成进产品 / 付费分发…>
预计规模：<用户数 / 实例数 / 年营收预估>
是否修改源码：<是/否；若是，说明打算怎么改>
希望的支持：<仅授权 / 需要技术支持 / 需要定制>
联系方式：<邮箱或其他>
```

作者收到后会书面回复是否同意、授权范围与条件（可能包含授权费、署名要求、版本范围、期限等）。
**在收到明确书面同意之前，请勿开始任何商业使用。**

## 四、发现未经授权使用怎么办

1. 保留证据（截图、链接、时间、数量）；
2. 通过 Issue 或作者主页联系方式告知作者；
3. 作者可视情况要求整改（补上授权或下架），必要时按 `LICENSE` 第十条走法律途径。

## 五、常见问题

**Q：公司内部用，不对外卖，算商业使用吗？**
算。集成进生产经营系统（哪怕只内部用）属于商业用途，需要书面同意。

**Q：我改了很多，还算「二改」吗？**
算。基于本软件的任何修改、拆分、合并、翻译、移植都受第四条约束。

**Q：能把它放到我的付费整合包里吗？**
不能直接放，需要商业授权。

**Q：能拿它引流卖别的服务吗？**
如果本项目是卖点的一部分，需要书面同意。

**Q：我只改了配置/提示词，也要开源吗？**
只改配置和提示词、不分发代码，不需要；一旦分发修改后的代码（包括 `main.py` 等），就要开源。

**Q：能不能换个更宽松的协议用？**
不能。以仓库 `LICENSE` 为准；如需其他授权，请与作者另行协商。

**Q：为什么不用 MIT？**
因为作者要保留商业化授权。MIT 允许任何人闭源商业化，与本项目目标冲突。
