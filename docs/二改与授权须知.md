## 一、先看场景速查

| 你的用法 | 是否需要付费 | 必须做的事 |
|---|---|---|
| 自己装来用、自己群/自己服务器 | 不需要 | 无 |
| 学习、研究、改着玩 | 不需要 | 无 |
| 改完按 AGPL 开源发布 | 不需要 | 附完整源码 + 保留声明 + 标注上游 |
| 公司内部使用（不修改） | 不需要 | 无 |
| 公司内部使用且修改，作为内部网络服务 | 不需要 | 按 AGPL §13 向使用者提供源码 |
| 集成进**闭源**产品 / 闭源内部系统 | **需要商业许可** | 签协议 |
| 做 SaaS、多租户，**不想开源修改** | **需要商业许可** | 签协议 |
| 打包进闭源发行版、付费课程、付费整合包 | **需要商业许可** | 签协议 |
| 换皮后当自己产品卖 | 需单独协商 | 通常不授权 |
| 以本插件为主要卖点做商业宣传 | 免费（若按 AGPL 开源） | 标注上游，不得称「官方」 |

> 判断标准：**你愿不愿意把修改按 AGPL 公开？**
> 愿意 → 免费；不愿意 → 买商业许可。AGPL 本身允许商用，商业许可卖的是「闭源也能用」。

## 二、按 AGPL 合规的三件套

### 1. 附完整源码

- 分发修改版本时，把完整源代码（含你的修改）一起给出去；
- 用 AGPL-3.0-or-later（或 GPLv3 兼容的更严协议）授权；
- 如果是网络服务：AGPL §13 要求向**通过网络与它交互的使用者**提供获取完整源码的方式
  （例如页面上放「获取源码」链接）；
- 不能只发编译产物、加密/混淆代码，或只开一个不收用户也收不到源码的 SaaS。

### 2. 保留声明

不得删除或篡改：

- 源文件头部版权行与 `SPDX-License-Identifier`；
- `LICENSE`、`NOTICE`、`ADDITIONAL-TERMS.md`；
- 界面/文档中原有的作者署名与许可声明。

### 3. 标注上游（依 AGPL §7(b) 附加条款）

分发修改版本时，至少一处（建议三处）写明：

- 原作者：`Bb18273645`
- 原始仓库：`https://github.com/Bb18273645/ChartSmith`
- 基于的版本或 commit：如 `v1.0.0` / 对应 commit
- 你的修改摘要

**README 模板：**

## 三、AGPL §13 到底管什么

AGPL 比 GPL 多出来的核心条款是第 13 条：

- 如果你**修改**了本插件，并让它**通过网络供他人使用**（SaaS、内部系统、机器人服务），
  你必须向这些使用者提供获取**完整源代码**的途径；
- 没有修改、只是原样部署，通常只需保留原有声明；
- 「内部使用」也要看：如果修改版通过公司内网供同事使用，严格来说同事也是「使用者」。

不想处理这些细节（或者必须闭源）→ 买商业许可，按协议用即可。

## 五、发现违规怎么办

1. 保留证据（链接、截图、时间、分发渠道、收费信息）；
2. 通过 Issue 或作者主页联系方式告知作者；
3. 作者可要求整改（开源其修改或补签商业许可），必要时按 AGPL 第 8/10 条终止授权并走法律途径。

## 六、常见问题

**Q：AGPL 是开源许可吗？**
是，OSI 承认的自由软件许可。它能上 GitHub 开源仓库、能通过 AstrBot 插件市场的开源审核。

**Q：能商用吗？**
能，但必须按 AGPL 开源你的修改并保留声明；不想开源就买商业许可。

**Q：我只改配置和提示词，需要开源吗？**
你分发的代码若未修改（`main.py` 等未动），按 AGPL 原样分发即可；提示词不是代码，另行创作不受限。
一旦分发修改后的代码，就要按 AGPL 开源。

**Q：内部自用也要开源吗？**
不修改、或修改后不通过网络提供给别人用：一般不需要。
修改后作为内部网络服务：按 §13 应向使用者提供源码，或购买商业许可。

**Q：为什么用双许可，不直接用 MIT？**
MIT 允许任何人闭源商业化且无需回报，作者无法获得商业收益，也无法要求二改标注上游。
AGPL + 商业许可兼顾了「社区自由使用」和「作者能商业化」。

**Q：能改成更宽松的协议吗？**
作者已发布的版本按发布时协议执行；如需其他授权，请与作者协商。

**Q：我买的商业许可包含哪些权利？**
见 [`COMMERCIAL-LICENSE.md`](../COMMERCIAL-LICENSE.md)：闭源集成、修改免公开、随产品分发，可协商支持/SLA。
